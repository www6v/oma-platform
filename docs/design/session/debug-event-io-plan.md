## Goal

In Console **Debug** tab, every event type shows clear **Input** and **Output** (or N/A). Tool use/result are bidirectionally paired. Noisy telemetry (`span.model_request_*`) is default-hidden in the filter, not deleted from storage.

---

## Scope Decisions

| ID | Choice | Meaning |
|----|--------|---------|
| D1 | **A** | Complete Debug I/O + bidirectional tool pair + default-hide spans |
| D2 | **A2** | Debug list keeps both `tool_use` and `tool_result` rows; either selection shows full I/O |

### Scope (accepted: A)

- Generic I/O rendering for all event types (field map, not one fancy widget per type)
- Bidirectional tool pairing (select use OR result → see both)
- Default-hide `span.model_request_*` via filter defaults
- Tests for I/O extractor + Debug pairing

### NOT in scope

- Deleting events from DB / event log
- Full typed renderer registry per SPEC type (that was option C)
- Changing Transcript tab UX (except shared lib reuse if trivial)
- Persisting streaming chunk events into Debug
- Backend schema changes

## Known bug (in scope)

`DebugTab` looks up `resultByToolUseId` by `primaryEvent.id`. Works when selecting `agent.tool_use` (id == tool use id). Selecting `agent.tool_result` hits unpaired branch → "tool result (unpaired)". Fix: resolve pairing from use→result AND result→use; pass both into EventDetail.

## Proposed design

```
events[]
   │
   ├─ pairToolResults → resultByToolUseId, useByToolUseId (NEW reverse map)
   ├─ pairModelSpans  (optional for span I/O)
   └─ getEventIO(event, ctx) → { input, output, labels }
            │
            ▼
     EventDetail Rendered
       [type badge]
       Input:  <json|text|empty>
       Output: <json|text|empty>
       (keep existing Tool/Message widgets for tool_use + messages as special cases)
```

### New module: `console/src/lib/event-io.ts`

`getEventIO(event, { pairedUse?, pairedResult?, modelSpan? })` returns structured I/O for:

| type family | input | output |
|-------------|-------|--------|
| user.message | content | — |
| agent.message | — | content |
| agent.thinking | — | text |
| *tool_use | name + input | paired result content |
| *tool_result | paired use input | content |
| team.message | from/to/payload | — |
| session.team_created | team members payload | — |
| session.lifecycle / status_* | phase / stop_reason | — |
| session.error / warning | — | error/message (+ cause) |
| span.model_request_end | model, start_id | usage, finish_reason, error |
| default | remaining fields minus meta | — |

Meta keys stripped from dump: `type`, `id`, `ts`, `processed_at`, `session_thread_id`, `seq`.

### DebugTab changes

1. Build reverse map: tool_use_id → use event
2. When rendering detail, if selected is result → pass `pairedUse` + show combined I/O
3. Initial filter: all types except `span.model_request_*` (chips still listed; greyed until toggled on). Easy "show all" / clear control.
4. Keep listing both use and result rows (Debug completeness) — **A2**

## Architecture review

No further issues after D1/D2.

- Reuse `lib/tool-pairing.ts`; add reverse index `useByToolUseId` (or lookup helper).
- New pure `lib/event-io.ts` for I/O extraction (testable without React).
- Keep rich Message / Tool / Reasoning widgets for message/thinking/tool_use; generic Input/Output block for all other types and as fallback.
- Default filter excludes `span.model_request_*` only; chips remain visible so users can opt in. Not DB delete.

Blast radius: console UI only. No harness/API wire changes.
